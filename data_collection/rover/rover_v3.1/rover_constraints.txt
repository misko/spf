# Fleet dependency constraints — the versions Rover 1 runs.
#
# WHY THIS EXISTS
# Every rover's Python environment was previously whatever PyPI served on its
# provisioning day. On 2026-08-04 the fleet was running three different zarr
# versions against production datasets, and Rover 4 -- the first rover
# provisioned in months -- had never been able to capture at all, because a
# fresh resolve installed numcodecs 0.16.5 against zarr 2.x and every capture
# process died importing `cbuffer_sizes`. The same mechanism removed `future`
# from under MAVProxy.
#
# Rover 1 is the reference: it has the longest run of known-good captures.
# Its complete environment is recorded in rover1_reference_freeze.txt.
#
# WHAT IS PINNED HERE, AND WHAT IS NOT
# This file pins the stack that determines DATASET FORMAT and MAVLINK
# BEHAVIOUR -- the things whose drift silently changes recorded data or
# vehicle interaction. It deliberately does NOT pin the compute stack
# (torch, numba, scipy): those do not change what is recorded, and forcing a
# multi-gigabyte torch downgrade during a boot-time `pip install` on a Pi is a
# far larger risk than the drift it would fix. Torch divergence is tracked
# separately (Rover 1 has 2.5.1, Rover 4 has 2.13.0).
#
# Applied by update_spf_before_boot.sh as `pip install -e . -c <this file>`.
# Constraints do not install anything by themselves; they only bound the
# version chosen for a package that is already being installed.
