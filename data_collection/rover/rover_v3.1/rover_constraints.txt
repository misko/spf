# Fleet dependency guard rails, applied by update_spf_before_boot.sh.
#
# THESE ARE RANGES, NOT EXACT PINS, AND THAT IS DELIBERATE.
#
# The boot updater runs `pip install -e . -c <this file>` before the radios and
# the collector start. Anything here that a rover does not already satisfy
# forces pip to resolve, download and -- for packages with no aarch64 wheel --
# COMPILE, while the boot waits.
#
# That is not hypothetical. An earlier version of this file pinned
# numcodecs==0.12.1 exactly. Rover 4 had 0.15.1, no aarch64 wheel exists for
# 0.12.1, and the boot updater sat compiling c-blosc/zstd from source with
# spf-pluto-direct-usb.service blocked behind it (Requires=) and the operator's
# capture blocked behind that -- in the field, at night. numpy==1.25.2 was
# queued next, which on a Pi is an hour or worse and may not build at all.
#
# So: this file exists ONLY to exclude version combinations that are KNOWN to
# break, and every bound here is one that the fleet already satisfies. It costs
# nothing at boot.
#
# To converge a rover onto Rover 1's exact versions -- which is a real thing to
# want, and what rover1_reference_freeze.txt records -- do it DELIBERATELY, on a
# bench, with the collector stopped:
#
#     sudo systemctl stop mavlink_controller.service
#     ~/spf-virtualenv/bin/python3 -m pip install -r \
#         data_collection/rover/rover_v3.1/rover1_reference_freeze.txt
#
# Expect source builds and budget an hour. Never at boot.

# zarr 2.x imports numcodecs.blosc.cbuffer_sizes, which numcodecs 0.16 removed.
# Unpinned, a fresh resolve installs 0.16.x and EVERY capture dies at import --
# which is exactly what happened to Rover 4 for its entire existence until
# 2026-08-04. The whole fleet is already below 0.16.
numcodecs<0.16

# zarr 3 removes LMDB support, which every v7 store depends on.
zarr<=2.18.4
